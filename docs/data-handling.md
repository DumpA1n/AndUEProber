# Data handling

Core consumes caller-provided memory readers and explicit sample addresses. Read operations expose bounds, budgets, deadlines, cancellation and module generation checks. A failed read never requests a different process, changes dumpability or modifies page permissions. The optional process adapter reads this process through `AndSwapChainHook::Memory`, pins a normal linker module with `RTLD_NOLOAD`, and records its GNU build ID and a monotonic lease generation. Missing dependencies, unsupported module providers and permission failures remain visible. No syscall-reader fallback is provided. Standard profile discovery uses bounded ELF and instruction helpers without address caches. Unsupported upstream profile providers, custom names, ProcessEvent discovery and full live SDK export are rejected before entering upstream readers.

The agent requires an explicit absolute export root. `publishExport` accepts a frozen validated snapshot and caller-owned file buffers. It rejects known failed/cancelled observations and absolute/traversing/duplicate/reserved file paths, and creates a unique `.staging-<session>-*` directory within that root. Its advisory lock serializes cooperating publishers. The caller owns the output root and must exclude untrusted concurrent filesystem mutations.

Files and directories are flushed before publication. Data is renamed to a new final session directory; completion is finalized separately as `completion.json`. Failure can retain a staging directory or a final directory with `.manifest.pending`. If final-marker durability fails, the exporter attempts to rename the marker back and flush that change. A failed rollback rename or directory flush sets `ExportResult::completionUncertain`; a completion marker can remain visible after a failed export.

`ExportResult::status` determines the calling operation's outcome. A failed status remains a failure even when `isCompletedExport` returns true. That boolean only checks for a visible regular `completion.json` outside a `.staging-*` directory; it does not validate manifest contents or prove filesystem durability. Callers must retain and handle `completionUncertain` rather than infer success from marker presence. Existing completed session directories are never replaced or deleted by the exporter.

The completion manifest records tool revision, supplied dependency revisions, module identity/generation, reflection layout and exact data-layout identity, offset values/origins/versions/dependencies/evidence sources and sample identities, generated filenames, byte counts and FNV-1a checksums. FNV-1a detects accidental differences; it is not a cryptographic integrity guarantee. Filesystem errors propagate to the caller. A final-marker failure preserves a failed status; `completionUncertain` additionally reports an unsuccessful or unconfirmed rollback.

The application owner controls retention of successful and incomplete session directories. Logs and generated reflection data can contain target identifiers, addresses, names and proprietary metadata. Real target dumps, credentials and private application materials are not public fixtures. No default upload is implemented in the first-party entry point; absence of all network activity is not claimed without corresponding runtime observation.

`AUEP_StartIndexProbe` copies the profile configuration; its array and object memory remains caller-owned until Stop joins. It publishes `observations.txt` and the completion manifest. Module lifetime does not freeze mutable object memory; the phase checks header, sampled object identities and index values before and after probing, and rejects observed changes. This is a bounded observation, not a guarantee of an engine-wide coherent snapshot. Cancellation after successful publication does not retract the completed directory.

Name-pool reads bound the block table, entry extent and Unicode length, then recheck the block pointer, header and payload. FName reads honor explicit comparison/display/number offsets and number suffixes. Name-field probing records exact anchor identities and strings, physical pool address and lease generation; changing an upstream offset invalidates dependent evidence. Layout identities serialize the pointer size and each array/name layout field, including zero and absent offsets. These observations do not freeze an engine's mutable state or authorize its allocator or thread access.

Class and outer phases consume explicit relationships between distinct owned/profile anchors. Class candidates resolve names through the bounded pool reader; outer candidates compare pointer identities, including null. Both phases reread matched pointers before publication. `FieldProbeReport` preserves candidate rejection offsets, sample identities, structured errors and reasons. An unmapped candidate does not hide permission, short-read, deadline, cancellation or generation failures. `beginFieldProbe` marks an automatic field and downstream observations stale before another attempt; `publishFieldProbe` records current dependency versions and keeps results based on unvalidated dependencies unvalidated.

Interactive commands copy their field names and values. The owner retains at most 16 pending commands; cancellation drops that queue. The inspector bounds user-created fields to 256 and diagnostic messages to 500. Its UI reads immutable snapshots, including diagnostic text that can contain object names or addresses. Snapshot publication copies all working containers. The same worker owns the memory lease across commands; resetting an operation budget preserves that lease's generation. Permission, cancellation and deadline checks also run after the provider returns. UI drawing does not read process memory or write export files.

`AUEP_StartStructProbe` copies bounded arrays, strings, extents and independently declared relationships before starting its worker. One 64 MiB budget and 30-second deadline cover module-note reads, four UObject fields, configured UField/UStruct probing and publication. The structure fields record Phase1 dependency versions; an override conflict fails while preserving the override value. Optional alignment is absent when its metadata is absent. No object-size field is fabricated. `struct-observations.txt` is generated only from the frozen result; the caller must keep object, pool, array and relationship storage alive until Stop joins.

`AUEP_StartClassProbe` extends the same copied setup and operation budget with independently declared CastFlags and default-object pointer metadata. Phase3 publishes both class fields atomically with validated UObject/UStruct dependency versions. Default-object pointers are compared and never invoked or dereferenced by this phase. Only the complete frozen pipeline is exported to `class-observations.txt`; failure in class probing does not publish an earlier struct result.

`AUEP_StartFunctionProbe` adds copied declared flags, parameter counts/sizes, return offsets and native pointer identities to the configured pipeline. Its five fields require distinct non-overlapping observations and final readback. The function addresses are not executable entry points exposed by this operation. `function-observations.txt` contains the complete frozen offset set; no previous pipeline stage is published separately.

`AUEP_StartFieldBaseProbe` deep-copies independent names, pointer identities and exact SeparateBoolean owner layout. The NamePool address and generation must match the Phase1 name evidence. Class addresses are opaque comparison values. The operation publishes only the five base fields and does not infer property/container layouts.

`AUEP_StartFunctionLayoutProbe` deep-copies a typed scalar schema and independent size/alignment declaration. `freezeReflection` resolves the five offset keys and versions from validated observations. Formatting consumes only that immutable object, and `publishExport` publishes the header, declaration and observations together. The completion manifest includes the checked detached-emitter dependency identity. A schema, formatting or publication failure cannot publish an intermediate observation as a completed result.

`AUEP_StartObjectFlagProbe` copies independent uint32 metadata and emits five UObject observations without a guessed flag mask. `AUEP_StartPropertyProbe` copies signed sizes/offsets, uint64 flags, a separate occupied FField prefix and containing-value declaration; it checks the preceding owner/name observation identities and full dependency closure. Property candidates cannot occupy inherited field storage.

`AUEP_StartEnumProbe` admits at most sixteen independently named objects, 16384 complete named entries and 4 MiB of entry metadata. Nested arrays and strings are copied before start returns; target arrays and name-pool storage remain caller-owned until Stop joins. Every signed value and complete resolved name is matched, and array headers/data are reread before publishing a frozen observation. Explicit header, entry and occupied-prefix layouts do not imply a generic UE version or ProcessEvent signature.

Configured Inspector views retain only an immutable snapshot for the frame and expose no command or cancellation controls. Interactive provider capabilities disable unavailable phase/export actions. Stopped observations remain drawable without retaining a target reader or module lease.

`AUEP_StartPropertyTailProbe` copies one explicit supported kind and three to sixteen independently named pointer samples. Dual-column kinds require an explicit second value, including zero; single-column kinds require it to be absent. The occupied FProperty prefix and complete preceding scalar/name/owner observation identities constrain admission. Target pointer addresses are compared only, including pointers into inaccessible owned mappings. This does not validate the pointed-to type, container storage or element ownership.

`AUEP_StartBoolPropertyProbe` copies independent storage extents, identities and all four uint8 values; it never reads containing property storage. `AUEP_StartFieldPathPropertyProbe` copies explicit inline-FName profiles and complete expected names. Referenced metadata and name pool memory remain caller-owned until Stop joins. Both operations share the preceding property evidence and publish only a frozen validated observation; no engine function or property-class target is invoked.
