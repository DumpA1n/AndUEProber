# Bounded evidence closure

`AndUEProber::Core` exposes `validateEvidenceClosure` through `andueprober/Evidence.hpp`. It validates selected offset roots and every transitive dependency in an immutable `Snapshot`. It does not read memory, change offsets or inspect unrelated offsets and field reports. Memory-backed callers retain their own module, layout and reader-generation checks before observation and publication.

Every selected node requires a value, a nonzero version, `Validation::Validated` and nonempty observation evidence. Offset zero remains a valid value. Evidence requires a passed check, nonempty source, a positive sample count and the same number of named sample identities. Names, sources and identities must be nonempty UTF-8 without embedded NUL bytes. Dependency versions must match the referenced nodes. Missing dependencies, cycles, stale or candidate ancestors, and invalid proof metadata return `InvalidEvidence`.

`EvidenceLimits` defaults are 4096 selected nodes, 16384 dependency entries, 4 MiB of accounted metadata and 1024 bytes per text entry. The default deadline is 30 seconds after the limits object is constructed; an optional atomic cancellation flag can interrupt traversal. The explicit stack avoids recursion. Shared ancestors count once, while each selected node's dependency entries count separately. Root occurrences consume root metadata and the root count limit even when duplicated.

Metadata accounting includes `sizeof` entry storage and text bytes for the selected graph and snapshot identity. It is architecture-dependent and does not cap total heap allocation. Unrelated snapshot storage is excluded. Each text entry is checked against its configured limit before UTF-8 validation. The traversal checks cancellation and deadline between bounded entries. This is a cooperative operation bound, not a wall-clock execution guarantee.

An empty root list or zero node, metadata or text limit returns `InvalidArgument`. A zero dependency budget permits leaf-only closures. Exhausted node, edge or metadata budgets return `BudgetExceeded`; text exceeding the per-entry limit is invalid evidence. Cancellation and expired deadlines return `Cancelled` and `DeadlineExceeded`. Allocation failures return `Internal`; an error message can be empty when message allocation fails, while the error code remains available.

Struct, class, function, field, property and object-flag probes validate required roots before reading and revalidate the roots and tentative outputs before publishing. Matching user overrides retain their value and version but must satisfy the same complete dependency closure. An unrelated stale result does not prevent these selected phases from succeeding. Full snapshot export retains its separate whole-snapshot validation contract.

`tests/evidence.cpp` checks bounded deep graphs, cycles, shared ancestors, invalid proof metadata, cancellation, deadlines and successive allocation failures. `tests/evidence_phases.cpp` uses actual owned Struct/Class/Function pipelines to check transitive invalid evidence, changes during reads and cyclic retained user outputs under both FField and UProperty layouts. The original phase regressions remain separate tests. `tests/component_consumer` calls the public closure validator on a snapshot produced by its actual scalar probe and frozen session, from a caller-owned DSO.

`python3 tests/verify_evidence.py --ndk /path/to/android-ndk` runs host Debug, Release and Debug ASan/UBSan fixtures, host source and relocated installed consumers, and Android AArch64 Debug/Release compilation. CTest rejects an empty test selection. The runner records selected source hashes, command output hashes and artifact hashes in [the evidence manifest](../tests/evidence/verification.json).

`python3 tests/run_evidence_android.py --serial DEVICE_SERIAL --ndk /path/to/android-ndk` verifies those artifact hashes, executes all six owned CLI fixtures in both Android configurations and the source/installed DSO consumers on the selected device, and records their actual output. It checks current selected sources before and after execution and preserves device SHA-256 values, build IDs, host UUIDs and matching symbols. The NDK can also be inferred from the producer cache. The runner refreshes the Structs, Classes, Functions and ObjectFlags manifests only after these runs pass. Cross-compilation alone is not runtime validation. The macOS sanitizer configuration does not claim LeakSanitizer coverage.
